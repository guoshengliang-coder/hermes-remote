# 本机 Hermes 只读版本管理（HG-199 拆分交付）

从草稿 PR #560 仅提取版本检测、升级条件检查与升级记录，放在“本机 Hermes”的“版本与升级”卡片。
GO app/后台组件继续使用设置页既有统一更新入口。本次不改变安装布局、PM 选择、launcher、协议或版本号。

- 版本检测使用既有本机安装识别结果，显示安装版本/commit、上游稳定发布、检查时间。
  官方 tag 解析到固定 commit；最新稳定版不等于 GO 推荐，推荐列表默认空。
  公共网络请求不继承凭据/cookie、拒绝重定向、限制 512 KiB，并共用 30 秒期限。
- 条件检查仅核验 Git 本地修改、已有升级恢复记录和官方更新标记。
  v1 标记沿用二十分钟期限；v2 按标记内精确 owner/delegate 的 PID 与创建时间核对，不按年龄忽略活跃更新。
  Git 使用只读/禁网/禁子进程沙箱、有限输出与期限；拒绝 filter/include 等检查器未支持的配置。
  自定义 SSH 命令等配置被明确标记为“自定义 Git 配置阻止安全检查”，不再混成未知失败；
  仅诊断固定拒绝类别，不展示配置值/路径/命令，不执行或修改配置，也不建议删除原配置。
  干净工作区也不授权升级，不调用 Hermes API 或扫描/停止业务进程。
- 升级记录只读 `hermes-upgrade-state.json`，区分未读取、无记录、无法核验、待恢复和历史终态。
  阶段表示最后记录的意图，不表示进程仍活跃；历史“已完成”不证明当前健康。
  私有 no-follow 读器拒绝链接、多链接、权限异常、过大/歧义 JSON、未知字段和读取中变化。
  不创建、更新、删除记录；待恢复/无法核验记录阻断既有自动重启、安装、修复和迁移，提供诊断入口。

只注册 Desktop 消费的 HR-HERMESUPDATE-001/002/003；Android、Web、Gateway、Connector 不消费本次新码，
其协议和发布物不变。测试夹具可生成样例记录，产品没有 journal 写入器、升级事务执行器或恢复执行器。
不包含 Python updater 资源、PM 实验、上游维护原型、备份执行或新的认证版本/路径。

一键升级与自动恢复执行保持关闭。后续独立范围仍需上游跨进程停写与旧版首次迁移保障、完整官方升级/
依赖激活/中断恢复链路，以及原服务、历史与基本业务验收。保留原 PR #560 跟踪这些未完成工作。
