# 图片附件：预览、编辑与看图需求

> 状态：HG-35 的需求整理与①②③联合契约，供产品、Stitch 和开发使用。
> 范围：Android `com.hermes.remote` 的会话聊天页——待发图片 chip、图片编辑器、消息内缩略图与
> 全屏看图器；中文为默认语言，所有文案需具备中英文版本。
> 本文描述已确认的产品约束，不授权改变网关、Hermes 上游或附件上传协议。

## 1. 目标与入口

用户发一张截图问问题时，应当能在发出**之前**确认自己选对了图、圈出要问的那一处、把敏感信息盖掉；
发出**之后**能在气泡里认出是哪一张，并一步点开、左右翻看。

HG-35 指出的三个断点：

| # | 断点 | 本文对应 |
|---|---|---|
| ① | 添加图片或拍照后，图片只能删除不能点击查看 | §2、§4 |
| ② | 图片不支持涂鸦圈中、裁切、打码 | §3 |
| ③ | 发送后的缩略图被裁切、点不开、多图不能左右滑 | §4 |

入口表：

| 入口 | 用户意图 | 打开什么 |
|---|---|---|
| 输入框上方待发图片 chip（58dp 缩略图） | 确认选对了图 / 想改图 | 看图器，chrome = 待发（关闭 / 编辑 / 删除） |
| 待发预览里的「编辑」 | 圈画、打码、裁切 | 图片编辑器（全屏 Dialog） |
| 消息气泡里的图片缩略图 | 看大图 | 看图器，chrome = 已发送（关闭 / 保存 / 分享 / ⋮另存为…） |

**编辑只作用于待发附件。** 已发送和 Hermes 发来的图片没有可写的去处；「标注后重发」是另一个功能，
需要另一次产品决策。文件 / PDF chip 仍然只能删除（见 §2.4）。

## 2. 待发附件条

### 2.1 结构

待发 chip 行位于输入框之上，`LazyRow`、8dp 间距、按附件 id 做 key（顺序即上传顺序）。
图片 chip 为 58dp 方形缩略图、12dp 圆角、裁切填充；文件 chip 为 190×58dp `surfaceVariant` 卡。
上限 6 个，单附件 6 MB，图片超限时自动缩到 2560px 长边。

### 2.2 点按语义

| 目标 | 视觉尺寸 | 点击盒 | 动作 |
|---|---|---|---|
| 图片缩略图 | 58dp | 58dp | 打开看图器预览 |
| ✕ 徽章 | 24dp 黑 @55% 圆盘 | **32dp** | 删除该附件 |
| 文件 chip | 190×58dp | — | 无（只有右侧删除按钮） |

✕ 小于 48dp 是 `DESIGN.md §5.7` 记录在案的例外：主目标 ≥48dp、点击盒已放大到视觉尺寸之上、
且**删除在预览里另有一枚 46dp 的全尺寸入口**。三条缺一不可。

### 2.3 预览动作

关闭 / 编辑 / 删除。**不提供保存、不提供分享**——待发图是用户几秒前自己选的文件，保存是空动作；
而且保存/分享要求路径通过缓存根校验，待发附件只有内存字节，硬造路径会撞上缓存淘汰。

预览里删除后不得把翻页器晾住：把当前项移到邻居（优先后一张，否则前一张），只剩一张则关闭预览。

### 2.4 为什么文件 chip 不可点

App 内没有任意文件的查看器；待发文件尚未上传，没有可交给系统查看器的路径。要做就得写临时文件 +
`FileProvider` + `ACTION_VIEW` + 「无应用可打开」（`HR-FILE-007`）的完整路径，是 HG-35 没有要求的
新面。与「文件附件卡整卡可点」（HG-12）的不对称是**有意的**：那是已收到、有路径的文件，
这是尚未发出、只有内存字节的附件。改动这一条前先读本节。

## 3. 图片编辑器

### 3.1 容器与形态

全屏 `Dialog`，沉浸式隐藏系统栏，chrome 带 `displayCutout` 内边距。**不是导航目的地**：导航只有
String 路由，位图传不过去；而沉浸式必须自己持有窗口。

自上而下：顶栏（取消 / 撤销 / 重做 / 完成）→ 画布 → 底部工具行（涂鸦 / 打码 / 裁切）→ 当前工具的
参数行（墨色与笔宽 / 笔刷档位 / 比例预设与旋转）。Stitch 可以重排视觉层级，但不要移动或删除语义。

图标用手绘 `strokeIcon`，**不用 Material**——`DESIGN.md §4.1` 对弹层的豁免不覆盖沉浸式编辑器。

### 3.2 三个工具

| 工具 | v1 做什么 | v1 不做什么 |
|---|---|---|
| 涂鸦 | 徒手描边，6 色 × 3 档笔宽，笔宽按长边比例 | 箭头 / 矩形 / 椭圆、文字、橡皮 |
| 打码 | 像素化笔刷，3 档笔刷大小 | 高斯模糊、用户可调块大小 |
| 裁切 | 8 手柄 + 移动、5 种比例预设、旋转 90°、重置 | 任意角度旋转、透视校正 |

打码用像素化而非模糊：`minSdk 26` 让 `RenderEffect`（API 31）变成两套实现两种观感；中文语境的
「打码」就是方块；块均值在足够粗的块尺寸下比模糊更不可逆。

### 3.3 手势

| 情形 | 行为 |
|---|---|
| 双指（任何模式） | 缩放 + 平移画布，**永不产生笔迹** |
| 单指 + 涂鸦/打码 | 落笔绘制 |
| 单指 + 裁切 | 拖动手柄或整体移动裁切框 |

模式隔离是硬要求：裁切模式下拖手柄**不得**漏出一条笔迹。

### 3.4 编辑模型

非破坏到「完成」为止：编辑是一个**操作列表**叠在底图上，不是逐步烘焙。

- 撤销 / 重做**按手势**，一次手势正好消掉一个看得见的东西；重置清空操作但保留裁切。
- 列表顺序即 z 序：**后画的马赛克会盖住先画的涂鸦**。
- 离开裁切模式后，框外的笔迹是**视觉裁掉、不是删掉**，放宽裁切能让它们回来。
- 转屏后操作列表必须还在（走 Saver）。
- **不提供「还原原图」**：保留原图会把待发附件最坏内存从 36MB 翻到 72MB；用户删掉 chip 重选即可。
  连带后果：对已编辑过的附件再次打开编辑器，从烘焙后的字节起步，已提交的裁切无法撤回。

### 3.5 输出

工作分辨率长边封顶 2560，在工作分辨率烘焙（只有一个像素空间，所见即所得由构造保证）。
输出一律 JPEG，文件名 `photo.png → photo-edited.jpg`，幂等，保持 ASCII（名字会传到 Mac）。

**原地替换、复用同一个附件 id**：保住 chip 在条里的位置。移除再添加会把它挪到末尾，而上传按
列表顺序进行——等于静默重排了用户即将发送的内容。

**未做任何编辑就点完成 = 原样返回原字节**，不解码、不重编码、不降采样。

## 4. 消息内缩略图与看图器

### 4.1 缩略图

| 张数 | 规则 |
|---|---|
| 1 张 | **完整显示，永不裁切。** 容器取图片自身宽高比，高夹在 `[110dp, min(320dp, 屏高 42%)]`，由高反推宽并以可用宽封顶——气泡随图变窄，**不留白边** |
| ≥2 张 | 2 列方格、6dp 间距、单元格高 132dp、圆角 14dp、**裁切填充**，末行单张留半宽 |

多图仍裁切是 2026-09-12 的**显式取舍**，不是未完成项：网格参差比裁切更难读，而截图分享绝大多数
是单图。要改成完整显示，需要 masonry 或统一中位比例，属于另一次设计决策。

未就绪的图显示 `HermesMark` 等待标记，失败显示破图图标。解码尺寸按实测单元格宽 ×2。

### 4.2 看图器

黑底、沉浸式、双指缩放 1–5×、双击复位/放大。多图时顶部居中一枚 `2 / 5` 文字计数药丸
（不用圆点：任意数量都可读，TalkBack 能念，且不需要新组件）。

**翻页范围是同一条消息内的多图**，不是全会话相册。

手势仲裁是硬规则：双指永远归缩放（全部消费）；单指且未放大**一概不消费**，把拖动让给翻页；
单指且已放大时平移并钳制，**只有钳制后真的移动了才消费**，于是放大态滑到边缘还能继续翻页。
平移必须钳制在图像范围内——放大后不得把图拖出屏幕。

看图器状态由聊天页持有并可跨转屏恢复，**存 id 不存下标**（图片会被重新补齐，下标会指向另一张）；
解析为空即自动关闭；返回键条件必须带上它，否则返回会同时关看图器并拉开抽屉。

## 5. 错误与状态

| 场景 | 必须呈现 | 用户可做的恢复 |
|---|---|---|
| 缩略图或大图解码失败 | 破图图标 / 看图器内一行「图片无法显示」+ `HR-MEDIA-004` | 无（图已损坏）；不得崩溃 |
| 待编辑图片无法打开 | `HR-MEDIA-004` 的本地化说明 | 换一张 |
| 编辑结果无法保存 | `HR-MEDIA-005`，并**明示修改仍在屏幕上** | 重试；编辑器不关闭、不丢操作 |
| 待发图仍在准备中 | `HermesMark` 等待标记 | 等待 |
| 图片上传中 / 失败 | 现状不变（上传标记 / 破图 + 点按重试） | 点按重发 |

所有错误遵循 `docs/ERROR_HANDLING.md`：稳定错误码、中英文短说明、可重试性和已脱敏的诊断信息；
不展示原始 HTTP body 或异常文本。`HR-MEDIA-004` 与 `HR-MEDIA-005` **不合并**——「你的工作没丢」
是恢复动作的一部分。

## 6. 无障碍与本地化

- 待发缩略图：`onClickLabel` = `查看图片` / `View image`；✕ 徽章 = `移除附件` / `Remove attachment`。
  两者必须能被 TalkBack 分别念出（此前同在一个无标签容器里）。
- 看图器：计数药丸读作 `第 2 张，共 5 张` / `Image 2 of 5`；关闭 / 保存 / 分享 / 更多 / 编辑 / 删除
  各有独立双语描述。
- 编辑器：每个工具、每个墨色、每档笔宽与笔刷、每个裁切手柄、撤销 / 重做 / 重置 / 取消 / 完成都要有
  可读描述；墨色**不能只靠颜色区分**，描述里要有色名。
- 所有触控目标遵守 48dp，例外只有 §2.2 那一处且已记录。

## 7. 必须覆盖的状态

| 状态 | 预期 |
|---|---|
| 单张竖长截图（914×2048） | 完整可见、气泡随图收窄、高度被钳住 |
| 单张极宽图（4000×400） | 高度落在 110dp 下限，宽度不超可用宽 |
| 2 / 3 / 6 张 | 规整 2 列方格，末行单张半宽 |
| 图片未就绪 / 解码失败 | 等待标记 / 破图，**不崩溃**、不留纯黑 |
| 看图器单图 | 无计数药丸，无翻页 |
| 看图器多图放大态 | 平移不换页，边缘可续翻，双击复位 |
| 待发条 1 张 / 6 张 / 混合文件 | chip 可点，文件 chip 不可点，✕ 都在 |
| 编辑器三种模式 | 工具行高亮当前模式，参数行随之切换，切换不丢操作 |
| 编辑器有 / 无未提交修改 | 取消时弹 / 不弹丢弃确认 |
| 深色、360dp 窄屏、fontScale 1.3 | 工具行与比例 chip 不截断，取消/完成始终可达 |
| 转屏 | 看图器回到原页；编辑器笔迹与裁切框仍在 |

不要只交付「正常单图」一张图。

## 8. 视觉约束与设计任务

- 照片上的 chrome 在**两种主题下完全一致**：黑底白字、46dp 圆钮、`Color.Black @58%`。底下是照片，
  没有 `surface`，深浅判定在那里没有主语。
- 批注墨色是独立色板（`DESIGN.md §2.8`），六色含白与黑两个逃生色；色卡带 1dp 白描环，选中态用
  加粗环 + 放大，不用勾。
- 编辑器不引入新的间距体系，沿用最近似页面的取值。
