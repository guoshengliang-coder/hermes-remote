## 故障和长负载

测试通过真实 Connector 子进程，使用本机回环模拟 Gateway、Hermes 和独立文件返回接口；固定 `FILE_DOWNLOAD_BYTES_PER_SECOND=1048576`，循环 2 MiB 合成文件并校验 SHA-256，同时发送小型 HTTP 隧道请求。没有模型调用、实际 Nginx 或外网整形。延迟统计是请求发出至小响应返回的绝对 P95，不能冒充真实手机聊天确认的延迟增量。

- 初轮控制隔离核心的 30 分钟负载：6,921 个小请求，P95 **8.53 ms**，业务连接始终为 1，文件 hash 一致。
- 大业务分片与共享预算的第二轮 30 分钟负载：3,705 个小请求，P95 **11.44 ms**，业务连接始终为 1，文件 hash 一致。
- 单向丢包：持续不回复第一条控制连接的 pong；超过 15 秒仍保留，到约 45 秒仅替换控制，原业务连接保留。初次测试 171 个小请求，P95 **5.63 ms**；最终源码复验 166 个小请求，P95 **15.49 ms**，两用例全部通过。
- 最终短回归还覆盖 512 KiB 上传与 1 MiB 独立 HTTP 下载并行、期间关闭控制，完整校验上传内容和下载 hash。

长测试运行时加载的是当时的构建快照。长测之后增加了取消/分片边界、业务独立暂停计时和诊断字段，这些由最终源码单测及短集成覆盖；没有将先前长测描述成最终提交的逐字节验证。

## 审查复盘

1. 独立 socket 仍共享网络出口，因此控制丢失只表示该链路异常，不直接判定本机 Hermes 停止。
2. 控制拥塞的持续时间不能用于业务暂停计时，修复后由连续 business suspect 单独计时，并有回归测试。
3. 分片必须保持同一业务流顺序；取消会清理发送与重组，迟到片段短期丢弃。队列满时文件按原请求失败策略处理，其他业务明确关闭受影响连接，不能静默丢消息。
4. 探测不信任任意入站消息或旧 pong；鉴权 nonce 属于当前 socket，绑定撤权继续关闭所有成员。
5. 云端记录失败不覆盖新模式的本机观察；观察仍会自然过期为 unknown。诊断区分 write_queue、round_trip_missing/slow/deadline、本机 state/reason 和云端写入失败，不记录凭据或聊天正文。
6. 代理模板、应用内空闲预算和发布后的实际配置需要分别核对；源码修改不能证明线上配置已生效。
7. 灰度和发布需要执行仓库独立门禁；没有提升版本、部署、开启线上开关或替代人工验收。
8. 首轮 CI 发现运维包只收集 `protocol/dist/index.js`，遗漏新增模块；同步修复运维包及 Desktop v1/v2 Connector 组件包，新增解包后实际 import 协议的回归。修复前两种 Desktop 产物均能复现模块缺失，不能仅凭源码构建通过就判断产物可用。

阈值、兼容和发布顺序见 [实现方案](HG_244_CONGESTION.md)。真实环境验收须按其中矩阵留存证据后再推进条目状态。
