# 定时任务界面需求

> 状态：Android 现有能力与既有设计决策的整理，供产品、Stitch 和开发实现/优化使用。  
> 范围：当前身份下的定时任务列表、新建/编辑、详情、运行历史和任务告警；不改变 Hermes 的 cron 协议或消息渠道配置。  
> 视觉与排版以 `docs/DESIGN.md` §5.18 为准（2026-09-12 照 Stitch 基线-定时任务列表 / 任务详情 重做）；
> 本文只讲行为与内容，两者冲突时以 §5.18 和代码为准。

## 1. 目标与边界

定时任务让用户把一段提示词按固定节奏交给 Hermes 执行，并明确知道：何时运行、上次是否正常、结果会投递到哪里、出现问题时该修复任务本身还是消息渠道。

- 数据必须严格按**当前身份/profile**隔离。切换身份后，列表、详情、模板创建、投递目标和操作结果都只允许来自新身份。
- 任务执行在 Hermes 端完成；手机负责查看、配置、触发和处理异常，不能承诺本地后台一定执行。
- 正常任务不刷“上次成功”存在感；列表优先帮助用户发现失败、未送达和逾期任务。
- 所有用户可见失败都应遵守 `docs/ERROR_HANDLING.md`：稳定 `HR-<AREA>-<NNN>` 错误码、双语短说明、可重试性和脱敏详情。不得把原始异常、HTTP body、提示词以外的敏感投递信息直接暴露为主文案。

## 2. 信息架构与入口

```
身份卡页 / 首页告警条
        ↓
定时任务列表
  ├─ 详情（查看、运行、暂停/恢复、编辑、删除、历史）
  └─ 新建 / 编辑（计划、投递目标、提示词）
```

| 入口 | 行为 |
| --- | --- |
| 身份卡页“定时任务”入口 | 打开当前身份的任务列表。 |
| 首页顶部告警条 | 仅任务自身失败/逾期时出现；点按打开任务列表并定位“需要你处理”分组。 |
| 列表行 | 整行打开任务详情。 |
| 右下 FAB | 新建任务。顶栏不放 `+`。 |
| 空态模板 | 带预填计划与提示词进入新建编辑页。 |
| 行尾溢出菜单 | 快速暂停/恢复、立即运行；编辑和删除在详情页。 |

列表与会话、机器人、消息渠道共用“告警条 → 分组列表 → 右下新建 FAB”的层次；任务行不放 leading 图标，整行点击与行尾操作不可混淆。

## 3. 任务列表

### 3.1 页面状态

| 状态 | 必须呈现 | 恢复行为 |
| --- | --- | --- |
| 首次加载 | 品牌加载态 | 等待；返回该页时刷新。 |
| 加载失败 | 本地化错误码、简短原因和 Retry | 重试只重新加载当前身份的任务。 |
| 空列表 | `暂无定时任务`、模板入口、`新建定时任务` | 选模板或新建。 |
| 有任务 | 告警条（如有）+ 分组列表 + FAB | 可进入详情或执行快速操作。 |

### 3.2 分组、状态与排序

任务固定按以下顺序分组，空分组不渲染：

1. `需要你处理`：上次运行失败、运行成功但未送达、或下次应运行时间已逾期；
2. `已启用`：正常运行的任务；
3. `已暂停`：暂停或禁用的任务。

单个任务状态优先级为：`失败` → `未送达` → `逾期` → `暂停/禁用` → `正常`。因此暂停的失败任务仍需在“需要你处理”中露出，失败且逾期只算一项失败。

### 3.3 任务行

```
名称（单行省略） · 8dp 状态点                          [⋮]
节奏 / 投递落点 · 上次异常结果（最多 2 行）
```

- 名称优先使用任务名称；缺失时使用提示词或 ID 的安全回退，不能留空。
- 状态只由标题旁 8dp 圆点承载：失败/逾期为坏状态色，未送达为警告色，正常为好状态色，暂停为中性灰。品牌主色不得兼任“成功”。
- 副行遵循 `节奏或落点 · 上次结果`：例如 `每天 08:30 · 投递到 钉钉`、`每 10 分钟 · 只存不发 · 上次失败`。
- 健康任务不得追加“上次成功”；异常任务才追加 `上次失败`、`未送达`、`已逾期` 或 `已暂停`。
- `只存不发` 是有效的默认投递选择，不可被显示为空或被误判为故障；`origin` 显示为“投递到来源聊天”。
- 列表显示人类可读的节奏，而非未翻译的五段 cron；无法可靠识别的表达式必须原样显示，不能猜测或改写为错误自然语言。
- 行尾是操作菜单，不显示“下次运行”时间；精确下次时间属于详情。整行可点，行尾菜单只放快速操作。

### 3.4 任务告警条与渠道根因

- 出现“需要你处理”任务时，列表顶部显示可点告警条，如 `2 个任务需要处理`；点按滚动/定位到该分组。
- 告警条使用 HealthStrip 语义：失败为 `errorContainer`，逾期为中性 `surfaceVariant`；左右内缩 16dp、圆角 12dp，不做通栏第二顶栏。
- 首页只有一个告警槽位，消息渠道与定时任务按**根因优先**合并：
  - 若任务明确投递到某个断线渠道，该任务失败计入渠道问题（例：`Slack 未连接 · 3 个定时任务受影响`），点按去渠道，而不占任务徽标；
  - 任务自身执行失败或逾期仍保留任务告警；
  - `origin` 无法确认具体平台，不做错误归属，保留任务独立告警。

## 4. 新建与编辑

### 4.1 空态模板与基本字段

空态需提供三个一键起点，并允许进入后继续编辑：

| 模板 | 默认计划 | 默认意图 |
| --- | --- | --- |
| 每日摘要 · 9:00 | 每天 09:00 | 总结项目、部署、故障和待关注事项。 |
| 每周审计 · 周一 2:00 | 每周一 02:00 | 执行依赖与安全审计。 |
| 每小时检查 | 每小时整点 | 检查紧急待关注事项。 |

编辑页字段顺序：名称（可选）→ 计划 → 结果投递到 → 提示词（必填）→ 创建/保存。页面内容可滚动，保存按钮随内容放置，不使用固定底栏。

### 4.2 计划编辑器

计划类型用 5 段 Material `SingleChoiceSegmentedButtonRow`（这是全 App 浮起胶囊的例外，因 fontScale 1.3 下五格需要更稳健的降级）：

| 类型 | 所需输入 | 生成规则 |
| --- | --- | --- |
| 每小时 | 分钟（00–59） | 在每小时的该分钟运行。 |
| 每天 | 24 小时制时间 | 每天该时间运行。 |
| 每周 | 至少一个星期 chip + 时间 | 可选多天；最后一个星期不可取消。 |
| 每月 | 日期（1–28）+ 时间 | 每月该日运行；限制 1–28 避免无效日期。 |
| 高级 | 五段 cron 表达式 | 直接保存原表达式。 |

- 切换常规计划类型时，应尽可能保留当前小时/分钟，避免用户重新输入。
- 在编辑器下方即时显示人类可读计划与可计算时的“下次：<时间>”。高级表达式不承诺本地计算下一次运行。
- 高级模式仅接受合法的五段 cron；无效时字段显错、显示格式提示 `分 时 日 月 星期`，并禁用保存。
- 提示词为空时禁用保存并提示“请输入提示词”。保存失败留在编辑页，显示可重试的本地化失败；成功后返回上一级并刷新列表。

### 4.3 结果投递目标

- 首项固定为 `只存不发` / `Saved only`，对应服务端默认 `local`。
- 其余目标由 Hermes 返回的可投递渠道决定；标签使用渠道展示名，不自行编造平台列表。
- 没有设置默认投递落点的渠道可见但禁用；在选项下明确说明应先到目标聊天执行 `/sethome`，避免“能选但永远收不到”的假成功。
- 投递目标加载失败时，编辑仍可选择“只存不发”；不得猜测其他渠道。

## 5. 任务详情与操作

### 5.1 详情内容

详情顶栏显示任务名，内容按以下顺序呈现：

1. 计划（人类可读）；
2. 状态卡：已启用/已暂停/已停用、下次运行、投递目标、上次运行时间和状态；
3. 上次投递或运行错误（如有）：先给本地化错误码与短说明，用户主动点“展开”才显示已脱敏诊断详情；
4. 操作区；
5. 提示词预览（最多 6 行，可省略，可复制、可展开全文）；
6. `运行历史（N）`：每项显示开始时间、结果状态和耗时。耗时由 `started_at` / `ended_at` 算出；
   运行编号、单次运行的日志入口和保留策略上游都没有字段，界面上不出现（裁决 2026-09-12）。

### 5.2 操作

| 操作 | 可用性与结果 |
| --- | --- |
| 暂停 / 恢复 | 互斥显示；成功后刷新状态并给短反馈。 |
| 立即运行 | 可在启用或暂停状态触发；成功后反馈“已触发”，随后刷新详情/历史。 |
| 编辑 | 打开编辑页，保存后回到更新后的任务。 |
| 删除 | 不可逆，必须 `AlertDialog` 二次确认，明确“将永久删除该定时任务”；成功后返回列表。 |

所有操作失败必须保持当前页面与任务内容，不得乐观伪造状态；可重试错误提供 Retry 或可重复触发的操作入口。

## 6. 视觉、交互与可访问性

- 视觉走 `docs/DESIGN.md` §2.1 的暖纸中性系统（`#FAF9F5` / `#0F1217`）。本行 2026-09-12 前写的是「冷蓝中性视觉系统」，
  那是 2026-09-10 换肤之前的说法，已作废。深色模式通过 Surface 层级区分，不用紫/粉色底。状态颜色仅用于状态点与
  副行结果那一段，不把整行涂成状态色 —— 节奏与投递落点不是失败。
- 列表行、告警条、按钮、FAB、下拉与星期 chip 都要有清晰可访问名称和至少标准触控目标。
- 计划、投递、状态和时间均有中文/英文文案；未知状态可保留原始状态文本作为次级诊断，但主文案不可为空。
- 任务详情的错误详情可展开/收起；默认隐藏技术原因，并对凭证、个人数据、频道配置及其他敏感字段脱敏。
- 列表在 fontScale 1.3、360dp 窄屏下：标题单行省略，副行最多两行；五段计划选择器不裁切关键标签；状态点与溢出菜单不得被文本挤出屏幕。

## 7. 验收矩阵

| 场景 | 关键验收 |
| --- | --- |
| 身份切换 | 任务、投递目标、详情和操作全部随身份切换；旧身份数据不短暂闪现。 |
| 空态 | 三模板和手动新建均可进入编辑页；模板预填正确。 |
| 节奏 | 每小时/每天/每周/每月/高级均可编辑；高级无效 cron 不能保存；每周至少保留一天。 |
| 投递 | 本地保存可用；可用渠道可选；无 home target 的渠道可见但不可选并说明原因。 |
| 分组 | 失败、未送达、逾期在“需要你处理”；正常在“已启用”；暂停在“已暂停”；优先级正确。 |
| 行文案 | 正常行不说成功；副行按“节奏/落点 · 结果”；原始 cron 仅在无法可靠解析时保留。 |
| 告警 | 任务告警条可跳到问题分组；渠道断线的明确投递任务归到渠道根因；`origin` 不误归属。 |
| 详情与历史 | 下次运行、投递目标、最后运行、错误、提示词、运行历史完整；错误默认脱敏。 |
| 操作 | 暂停/恢复/立即运行/编辑成功后刷新；失败不伪造成功；删除须确认且返回列表。 |
| 视觉 | 浅深色、360dp、fontScale 1.3、长名称、长提示词和大量历史都可读可操作。 |
