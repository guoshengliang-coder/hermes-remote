Loading 动效体系 · 从启动图标衍生

目标：把全 App 的"正在加载"从 Material 默认转盘和无品牌的蓝点，统一成一套可缩放、可解释、由启动图标推导的动效。 本文是设计稿，尚未实现；方向选定后再落 DESIGN.md §5.6 与代码。动画在浏览器里实时播放，PNG 截图只能看到某一帧。

折面色板（取自 512px 源图）每色两档 = 一个受光面 + 一个背光面，光源方向全图一致。 启动页进度条已经在用其中三色 #1F84FD / #3DA340 / #FEC302。

四条可用的结构事实：

  • 四色四象限，顺时针 红 → 黄 → 绿 → 蓝：天生的四拍序列器，任何 4 步循环都能对上。
  • 单一光源的折面：每个色块的明暗只由"光从哪来"决定 —— 所以转动光而不是转动形状，就是这枚图标自己的动效逻辑。
  • 横梁是桥：H 的横梁把两条腿连起来，正好是产品本体（手机 → 网关 → Mac）。"东西正在过桥" = 正在工作。
  • 中心 C 是唯一汇聚点：四色、四条折线全交于横梁中心，天然的旋转轴与收束点。

轮光光绕 C 旋转，折面依次被照亮。方向 1
中继亮段从左腿过横梁到右腿。方向 2

汇聚四点向 C 收束。否决四个点在 12dp 下糊成一团，且与"发送中呼吸环"撞形。

3. 三条系统规则（先定规则，再选形态）

1

多彩只属于"品牌时刻"，页面内一律单色 primary。 依据 DESIGN.md §1 原则 3（chrome 永远蓝）与 §2.1（状态色独立于品牌色）。 多彩形态只出现在启动门（已定）和未来的"更新完成"一类一次性庆祝；会话列表、聊天页、设置页里的加载全部是 primary 单色 + 透明度。 理由不只是规范洁癖：加载动效里出现绿色会与 StatusColors 的"已完成 / 已连接"抢语义。

2

一个周期 1200ms，一个延迟门 250ms + 200ms 淡入。 1200ms 已经是发送呼吸环和启动流光的周期，全部动效对齐它，不引入第四条曲线（§5.6：新动效先对齐既有时长）。 延迟门沿用两处既有决策（气泡呼吸 250ms、启动状态 700ms）：加载在 250ms 内结束就什么都不出现，快的操作只看到内容直接出现。

3

不确定进度 = 品牌标记；确定进度 = 品牌渐变条。 两者不混用：不知道要多久的用标记（永不显示假进度），知道百分比的（上传、下载、更新）用渐变条 / 弧。 无障碍：reduce-motion 或省电模式下所有循环停在最亮一帧的 60%，保留静态标记与文字，不做动画。

4. 通用标记 · 三个方向对比

同一枚标记要在 48 / 32 / 20 / 14 / 12dp 五档都成立（页空态 → 行内）。下面每格都在实时播放，浅色深色各一份。

方向 1 · 折面轮光建议 锥形渐变的亮瓣绕 C 顺时针转，1200ms 匀速，形状不动。
优 连续、无机械感；12dp 下仍读得出"H 在转光"；就是图标自己的明暗逻辑。
劣 需要 sweepGradient + clipPath，比转盘贵一点。
方向 1 · 深色亮瓣用 Blue80，暗部 24%，深底上不发灰。
方向 2 · 横梁中继H 常驻 22%，一段亮光从左腿经横梁扫到右腿，1200ms。
优 叙事最贴产品：数据正在从 Mac 过桥；与启动进度条的流光同源。
劣 20dp 以下亮段只剩几像素，退化成"整体闪一下"；方向性强，只适合"连接 / 传输"，用在"列表在读本地缓存"上语义过头。
方向 3 · 四折面轮转四象限按 红→黄→绿→蓝 的位置顺时针逐个点亮，每拍 300ms。
优 最抗缩小（12dp 下就是四个方块在轮转）；实现最简单。
劣 离散的四拍偏"数字化 / 忙碌"，与 App 其余动效的连续感（呼吸、流光）不是一路；横梁在拍与拍之间会闪断。
品牌时刻 · 多彩轮光方向 1 的多彩版：四象限各自本色，白/黑亮瓣绕 C 转，等于"图标在呼吸"。 只准用在启动门（替代或补充现有 144dp 静态图标）与一次性庆祝，不得进入任何页面内加载。
